# AI decision-support agent for real estate investment

An agent that prepares an investment decision for a value-add office deal. It was built for the Braxton Asset Management case study on **Hélios**, an office building in Paris 9e (Paris QCA). The deal is described in a single configuration file, so the agent can be run on other assets.

From the deal file, the agent:

1. collects market data from public sources (transactions, rents, yields, rates, indices, planning, energy);
2. computes the financial model in Python (costs, quarterly cash flows, debt, IRR, yield on cost, value creation, breakevens);
3. scores the risks, runs sensitivities and scenarios;
4. issues a recommendation (**GO / GO SOUS CONDITIONS / NO-GO**) with a maximum price, conditions and documents to request from the seller;
5. writes an offline, interactive dashboard where every figure shows its source.

> Language note: the code comments, the dashboard and the generated texts are in French.

---

## Design principles

| Principle | How it is enforced |
|---|---|
| **The code computes, the LLM interprets** | All arithmetic is plain Python (`finance/`, `risk/`, `decision/`). The LLM only writes text. Its output is checked: every number must exist in the computed results, the note must start with the decision set by the rules, and no return target may appear. If a check fails, the text generated by the code is used instead. |
| **No invented data** | Every value is a `DataPoint` (value, unit, source name, URL, data date, method, status, confidence). A value that cannot be found is `missing`. An estimate is an `assumption` with a written justification. |
| **Nothing deal-specific in the code** | Deal data lives only in `asset_config.json`. Fund targets live in `config/investor_targets.yaml`, research parameters and modelling assumptions in `config/defaults.yaml`, sources in `config/sources_catalog.yaml`. |
| **Verified sources only** | Each connector was written from the official documentation or from a real response (`scripts/probe_sources.py`). Sources that could not be verified are flagged as such in the catalogue. |
| **Tested** | Every financial function has pytest tests, including golden cases and an independent IRR check. |

## Architecture

The agent is a [LangGraph](https://github.com/langchain-ai/langgraph) state graph with exactly eight nodes (`agent/graph.py`). All nodes share one `AgentState` (`agent/state.py`).

```
        identify_data_needs
                │
        research_market_data ◄──────┐  missing priority data: research again (2 times at most)
                │                   │
        validate_research ──────────┘
                │
        ┌───────┴────────┐
 financial_analysis   risk_analysis          (in parallel)
        └───────┬────────┘
       sensitivity_analysis
                │
        scenario_analysis
                │
     investment_recommendation               (waits for financial, risk and scenario)
```

| Node | Role |
|---|---|
| `identify_data_needs` | Lists the data the analysis needs (21 needs for Hélios), with a priority and the acceptable sources. |
| `research_market_data` | Calls the source connectors and fills the `DataRegistry`. |
| `validate_research` | Checks completeness, freshness, sample sizes and cross-source consistency; sends the agent back to research if priority data is missing. |
| `financial_analysis` | Runs the financial engine (`finance/`) and the maximum price. |
| `risk_analysis` | Scores risks on a probability × impact matrix (`risk/`). |
| `sensitivity_analysis` | Tornado, breakevens (rent, exit yield, capex) and heatmaps. |
| `scenario_analysis` | Favourable, central, unfavourable and stress scenarios, with their assumptions and annual cash flows. |
| `investment_recommendation` | Applies the decision rules, writes the note, the explanation and the dashboard. |

### Decision logic (`decision/`)

The recommendation does not rely on any return target: the case sets none, so `investor_targets.yaml` is empty. Instead, it reads the deal from seven angles, each compared with a market reference or with the model's breakeven:

1. purchase price vs comparable transactions (DVF);
2. relet rent vs market rents;
3. total cost per m² vs the value of a restructured building;
4. value creation in the central scenario;
5. yield on cost vs exit yield and cost of debt;
6. resilience to unfavourable and stress scenarios;
7. identified risks.

Each angle is rated *favorable*, *à surveiller*, *défavorable* or *non évalué*. The decision follows:

- **NO-GO**: value is destroyed in the central scenario, or the price is out of negotiable range;
- **GO SOUS CONDITIONS**: at least one angle is not favourable, or a critical risk remains;
- **GO**: all seven angles are favourable;
- **NON DÉTERMINÉ**: required market data is missing.

**Maximum price** = the lower of two references:
- the value breakeven (the price at which the margin on cost falls to zero);
- the comparable-transaction ceiling (DVF median price per m² × current surface).

## Installation

Tested with Python 3.13.

```bash
cd helios_agent
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS / Linux: source .venv/bin/activate
pip install -r requirements.txt
```

Node.js is optional. It is only used by the tests that check the dashboard's JavaScript slider engine against the Python engine; without it, those tests are skipped.

### LLM key (optional)

The text is drafted by `gpt-4o-mini` (set in `config/defaults.yaml`, section `llm`). The key is read from an environment variable and is never written to a project file.

```bash
# Windows (cmd)
set OPENAI_API_KEY=your_key
# macOS / Linux
export OPENAI_API_KEY=your_key
```

Without a key, the full analysis still runs. The texts are then the ones generated by the code, and the dashboard says so.

## Running the agent

```bash
python run.py                                   # analyses asset_config.json
python run.py path/to/other_asset.json          # another deal
python run.py other_asset.json --out output/other_asset   # keep each deal's results separate
python run.py --offline                         # no network: replays cached responses only
```

The configuration is validated before any request. A typo in a field name or an inconsistency (for example, an exit before the relet year) stops the run with an explicit message.

### Outputs (`output/`)

| File | Content |
|---|---|
| `dashboard.html` | Self-contained interactive dashboard: verdict, seven-angle grid, market, profitability, risks, scenarios, simulator, go/no-go note, sources. Works offline. |
| `analysis_results.json` | Financial results, risks, sensitivities, scenarios, recommendation. |
| `data_registry.json` | Every DataPoint with its source, date, method, status and confidence. |
| `validation_report.json` | Completeness and consistency checks on the collected data. |
| `run_log.txt` | Run log: research passes, missing data, assumptions, unavailable sources. Read this first. |

In the dashboard, every figure carries a pill (*saisi*, *calculé*, *hypothèse* or a source). Clicking it shows where the figure comes from. Unavailable values are displayed as « non disponible ». The only computation done in the browser is the simulator, which re-runs a JavaScript port of the Python engine.

## Data sources

The full list, with access details and verification notes, is in `config/sources_catalog.yaml`.

| Domain | Source | Access | Coverage |
|---|---|---|---|
| Geocoding | IGN Géoplateforme | API | France |
| Transactions | DVF+ (Cerema) | API | France |
| Transactions | Firmio (data.gouv.fr), business premises prices from DVF | file | France |
| Office market | ImmoStat: rents, take-up, supply, investment prices | Excel file | Île-de-France |
| Office market | Cushman & Wakefield MarketBeat Bureaux IDF | PDF report | Île-de-France |
| Prime market | Global Icons, prime market Paris QCA | web page | Paris QCA |
| Rates | ECB, Euribor 3 months | API | — |
| Indices | INSEE: ILAT, ICC, BT01 | API | France |
| Planning | Paris Open Data, PLU (protected buildings, heights, footprint) | API | Paris only |
| Energy | ADEME, commercial DPE | API | France |
| Natural risks | Géorisques (BRGM) | API | Reachable from France only |

Unverified or rejected sources stay in the catalogue with `verified: false` and the reason. For example, an aggregator was rejected because its prices are apartment medians, unusable for offices. When Géorisques cannot be reached, natural risks are reported as *not evaluated*, never as *absent*.

## Analysing another asset

1. Copy `asset_config.json` (for example to `configs/my_asset.json`) and fill in each section:
   - `asset`: name, type, district, submarket, reference address, surfaces before and after works, current and target DPE;
   - `operation`: asking price, capex per m², fees and contingencies, current leases, occupancy;
   - `financing`: LTV and margin;
   - `timeline`: acquisition date, works start and duration, relet year, exit year.

   Fields ending in `_pct` are fractions (`0.15` = 15 %).
2. Optional: put values from your own deals in `overrides`. They replace the agent's estimate and are shown as user input. Allowed keys: `acquisition_fees_pct`, `rent_free_months`, `exit_yield_pct`, `relet_rent_eur_sqm_year`, `sale_costs_pct`, `stabilised_occupancy_pct`, `non_recoverable_costs_pct`, `euribor_3m_pct`, `letting_period_months`.
   ```json
   "overrides": {"acquisition_fees_pct": 0.075, "rent_free_months": 12}
   ```
3. Run `python run.py configs/my_asset.json --out output/my_asset`, then read `run_log.txt` and open `dashboard.html`.

What carries over, and what does not:

- **Offices in Paris QCA:** works as is.
- **Another Paris or Île-de-France submarket:** add it under `submarket_zones` in `config/defaults.yaml`, with the matching ImmoStat zone and C&W row label. The Global Icons page covers the QCA only, so set `exit_yield_pct` in `overrides`.
- **Outside Paris:** the PLU data is unavailable and reported as missing. Outside Île-de-France, market rents and yields will be missing too; supply them through `overrides`.
- **Another asset type** (retail, logistics, residential): the DVF filter and the modelling assumptions in `defaults.yaml` are calibrated for offices and must be adapted.
- **Another strategy:** the model is built for a value-add operation with a works period. A core deal without works is not supported.

## Tests

```bash
python -m pytest -q
```

The suite covers:
- configuration validation and the data registry;
- connectors, replayed from recorded real responses;
- the research loop;
- the financial engine, with golden cases and an independent IRR check;
- risks, sensitivities and scenarios;
- the decision rules;
- the LLM output controls;
- the dashboard pipeline;
- the parity between the JavaScript and Python engines.
